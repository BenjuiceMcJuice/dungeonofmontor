# 2026-09-23 — Platformer mode spec (Montor's Descent)

## What

Specced a new version of the game: **Montor's Descent**, a room-by-room side-view platformer that keeps the same mechanics, content and sprites as The Crawl. Design only — no code yet.

Spec: `dom-app/docs/platformer_mode_spec.md`

## Key decisions

- **Third Tavern mode**, alongside Montor's Crawl (turn-based) and Montor's Tale (narrative). Not a fork — reads the same `src/data/*.json` and calls the same `lib/` engine functions.
- **One chamber = one screen.** The existing 4x4 zone maze (`generateMaze`/`generateZone`) is reused; maze connections become side doors (L/R), ladders/hatches (up) and drop holes (down).
- **Hidden dice.** Physical hit detection decides *if* you connect; the existing d20 4-tier resolver decides *how well* (crit/hit/glancing/miss), with a +4 "connected" bonus. Traps, searches, crits, loot all still roll.
- **Stats keep their Crawl meaning** plus a movement feel (AGI = speed/attack speed/i-frames, END = stamina + weight affects jump, PER = reveals secrets, etc.).
- **"Montor tick"** — a global 1 s tick replaces the turn for conditions, regen and bomb fuses, so `tickConditions` and reactions work unchanged.
- **Weapon classes become movesets** (dagger combo, spear reach/pogo, mace overhead stagger, axe wide arc, sword balanced, fists grab/throw).
- **Enemy AI behaviours** (flee, howl, heal ally, eat corpse, sacrifice, slime coat, spawn) mapped to movement patterns per archetype.
- **Art:** existing sprite grids reused at native size with tier colour swaps; new art (knight animation frames, 16 px tiles, side-view doors) drawn in the same K/C/S grid format.
- **Tech:** plain canvas 2D, fixed-timestep loop in `src/platformer/`, React only for overlays (inventory, merchant, gifts, StatPicker reused). No game engine dependency.
- 5-phase build plan (P0 feel prototype -> P4 polish) added to DEVLOG.
